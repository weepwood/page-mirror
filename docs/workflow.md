# 1:1 网站复刻工作流程

目标是复现原网站本身，而不是做一个“风格类似”的新网站。每次复刻都按本流程留存证据与验收结果。

## 1. 建立项目记录

- 创建唯一站点目录：`sites/<slug>/`。
- 记录原站 URL、访问日期、页面/路由清单、目标视口尺寸与页面状态。
- 记录必要的登录、地区、Cookie、弹窗等前置条件；不要保存真实凭证或用户数据。
- 为长页面、关键区块、悬浮菜单、弹窗、表单状态、滚动后状态建立截图清单。

## 2. 研究原站

对照原站逐项记录，而不是只看首屏：

- 页面结构：导航、容器宽度、栅格、区块顺序、间距、页脚。
- 视觉样式：字体、字号、字重、行高、颜色、边框、圆角、阴影、图标。
- 素材：图片、视频、字体、SVG、背景、裁切方式和加载状态。
- 交互：导航、下拉菜单、轮播、选项卡、滚动触发、键盘操作、表单反馈。
- 响应式：桌面、平板、移动端断点、折叠行为和溢出处理。
- 动效：触发时机、持续时间、缓动、滚动关联和加载过渡。

对动态内容与无法访问的状态明确标记，不要把猜测当成事实。

## 3. 实现策略

1. 先复现页面骨架和区块尺寸，再校准字体、颜色、间距和素材。
2. 优先使用与原站一致的可合法使用素材；不要用相似占位图冒充已还原。
3. 对交互逐一实现真实行为，而不是只做静态外观。
4. 避免用大量绝对定位硬凑截图；页面应在相同视口与滚动状态下稳定对齐。
5. 保持站点代码、样式、资源和说明独立；公共脚本只在确有复用价值时提取。
6. 若站点使用构建工具，提交可复现的依赖声明和构建说明；不要提交密钥、构建缓存或依赖目录。

## 4. 对照验收

在相同视口尺寸、相同滚动位置、相同交互状态下进行原站与镜像的并排比较。

- [ ] 所有目标路由均存在，导航目标正确。
- [ ] 首屏、主要内容区、页脚和长页面顺序一致。
- [ ] 容器宽度、对齐、留白、字体层级和换行接近原站。
- [ ] 图片、视频、图标、字体与裁切方式一致或有明确记录的差异。
- [ ] 菜单、按钮、轮播、弹窗、表单和滚动交互正常。
- [ ] 桌面和移动视口均检查，无明显溢出或布局崩坏。
- [ ] 浏览器控制台无未解释的错误，网络请求无不必要的失败。
- [ ] 刷新、直接访问子路由和返回导航均可用。
- [ ] 生产部署路径下的资源 URL 正确。
- [ ] 未完成项、受限内容、动态差异和素材授权状态已写入说明。

只有完成对照验收后，才将状态更新为 `completed`。视觉相似但交互未实现，不算完成。

## 5. 登记与部署

1. 更新 `sites/registry.json`。
2. 更新站点的 `README.md` 和验收清单。
3. 运行 `node scripts/validate-registry.mjs`。
4. 提交代码并检查 GitHub Actions。
5. 检查 GitHub Pages 线上预览地址，特别确认项目子路径下的静态资源。
6. 若线上验证失败，状态保持 `review` 或 `building`，修复后再验收。

## 6. 每个站点的交付记录

每个子项目的 README 至少写明：

- 原站 URL 与复刻范围
- 技术栈、启动和构建方法
- 本地预览方式
- 页面/路由清单
- 关键交互实现情况
- 验收视口、验收日期与结果
- 已知差异、阻塞项和素材许可备注
